Read an exam score from the user, convert to integer, store in score
Topic: input() · int() · type conversion · variables
🧠 Plain English
input() is like asking someone a question out loud — they speak back, and whatever they say comes back as text (a string). Even if they say "90", Python sees it as the word "90", not the number 90. You can't do maths on text, so you wrap it with int() to convert it to a whole number.
🌍 Kenyan analogy
A cashier reads a price tag that says "250". They read the text "250", but to add it to your total, they need to treat it as the number 250. int() does exactly that — converts text into a number you can calculate with.
python
score = int(input("Enter your exam score: "))
input("...")Shows the prompt, waits for the user to type. Always returns a string.
int(...)Converts the string to an integer so you can do maths.

A·II
if-elif-else block: assign letter grade + print Pass/Fail
Topic: conditionals · elif chains · boolean expressions
🧠 Plain English
An if-elif-else chain is like a bouncer checking questions one at a time. As soon as one condition is True, it acts and immediately skips all the rest. It never goes back to check further conditions once it finds a match.
🌍 Kenyan analogy
Think of a HELB eligibility form: "Are you below 18? Are you 18–25? Are you over 25?" As soon as one box is ticked, you stop. You don't check the rest.
python
score = int(input("Enter your exam score: "))

if score >= 90:
    grade = 'A'
elif score >= 80:
    grade = 'B'
elif score >= 70:
    grade = 'C'
elif score >= 60:
    grade = 'D'
else:
    grade = 'F'

if grade in ['A', 'B', 'C']:
    print('Pass')
else:
    print('Fail')
elif score >= 80Only runs when score was already confirmed below 90 — no need to write score < 90 again.
elseCatch-all — catches anything below 60 without writing score < 60.
grade in [...]Checks membership in a list. Cleaner than grade=='A' or grade=='B' or grade=='C'.

A·III
What happens if elif score ≥ 60 is placed BEFORE elif score ≥ 90?
Topic: elif ordering · logical bugs · dead code
🧠 Key concept
Python checks conditions top to bottom and stops at the first true one. A score of 95 is also ≥ 60 — so if that check comes first, the student gets 'D' and Python never reaches the condition for 'A'. Those upper checks become dead code — code that can never execute.
💡 Rule of thumb
With overlapping ranges, always check the highest threshold first, working down. Place the tightest filter at the top so wider conditions below don't accidentally catch more specific cases.
✗ WRONG ORDER
if score >= 60:   # 95 matches here!
    grade = 'D'   # Wrong — stops here
elif score >= 70:
    grade = 'C'   # DEAD CODE
elif score >= 80:
    grade = 'B'   # DEAD CODE
elif score >= 90:
    grade = 'A'   # DEAD CODE
✓ CORRECT ORDER
if score >= 90:   # 95 → 'A' ✓
    grade = 'A'
elif score >= 80:
    grade = 'B'
elif score >= 70:
    grade = 'C'
elif score >= 60:
    grade = 'D'

A·IV
OOP Pillar 2 — Inheritance: parent Animal, subclass Dog
Topic: class inheritance · method overriding · DRY principle
🧠 Plain English
Inheritance lets one class automatically get all the attributes and methods of another. The child class can then extend (add new things) or override (replace) any method from the parent — while keeping everything else for free. No copy-pasting code.
🌍 Kenyan analogy
Think of a Matatu. All matatus are Vehicles — engine, wheels, can move. The matatu inherits all that from the Vehicle blueprint. But it also adds its own things: route number, tout, set capacity. The matatu didn't redesign "movement" — it just extended Vehicle.
💡 Why use it?
DRY — Don't Repeat Yourself. Write shared behaviour once in the parent. Every child class gets it automatically. Change it in one place — not in 10 classes.
python
# ── PARENT CLASS ──────────────────────────────
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return f"{self.name} makes a sound."

    def breathe(self):
        return f"{self.name} breathes air."


# ── CHILD CLASS ───────────────────────────────
class Dog(Animal):    # Animal in brackets = inherits from Animal

    def speak(self):         # OVERRIDES parent's speak()
        return f"{self.name} says: Woof!"

    def fetch(self):         # NEW — only Dog has this
        return f"{self.name} fetches the ball!"


# ── TESTING ───────────────────────────────────
rex = Dog("Rex")
print(rex.speak())    # Rex says: Woof!   ← OVERRIDDEN
print(rex.breathe())  # Rex breathes air. ← INHERITED
print(rex.fetch())    # Rex fetches the ball!
class Dog(Animal)The brackets declare Animal as the parent. Dog inherits everything from it.
speak() in DogReplaces Animal's version. Python finds Dog's speak() first.
breathe()Not written in Dog — but rex.breathe() works because it was inherited.
selfAlways the first parameter. Refers to the specific object calling the method.
__init__Constructor — runs when you create an object. Dog uses Animal's since it doesn't define its own.
What does rex.breathe() return? (Dog doesn't define breathe)

OOP Pillar 3 — Polymorphism: process_shape() with Circle and Rectangle
Topic: polymorphism · duck typing · no isinstance()
🧠 Plain English
Poly = many, morph = form. Polymorphism means different objects can respond to the same method call in their own unique way. Your function doesn't need to know what type of object it has — it just calls the method and trusts each object to handle it correctly.
🌍 Kenyan analogy — M-Pesa
When you tap "Send" on M-Pesa — sending to a Safaricom number, Airtel, bank, or paybill — the same action produces the right result for each. You don't need a different app per type. One action, many implementations. That's polymorphism.
💬 This is called Duck Typing in Python: "If it walks like a duck and quacks like a duck, treat it like a duck." Python only cares that the object has the methods being called — not what type it is.
python
import math

class Circle:
    def __init__(self, radius):
        self.radius = radius
    def area(self):
        return math.pi * self.radius ** 2
    def describe(self):
        return f"Circle with radius {self.radius}"

class Rectangle:
    def __init__(self, width, height):
        self.width  = width
        self.height = height
    def area(self):
        return self.width * self.height
    def describe(self):
        return f"Rectangle {self.width}x{self.height}"

# No type-checking. Just calls .area() and .describe().
# Any object with these methods will work — that's polymorphism.
def process_shape(shape):
    print(f"Shape: {shape.describe()}")
    print(f"Area:  {shape.area():.2f}")

process_shape(Circle(5))
process_shape(Rectangle(4, 6))
What would happen if you passed a Triangle (with area() and describe()) to process_shape()?

OOP Pillar 1 — Encapsulation: private attributes, getters & setters
Topic: encapsulation · private variables · data protection
🧠 Plain English
Encapsulation means bundling data and the methods that operate on it into a single class — and restricting direct access to internal data. It protects data from being changed in invalid or accidental ways.
🌍 Kenyan analogy — ATM machine
An ATM encapsulates your balance. You can't reach in and change the number directly — you interact through controlled operations: withdraw, deposit, check balance. The bank hides the internals and exposes only safe, validated access. That's encapsulation.
python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner    = owner
        self._balance = balance  # _balance is "private"

    def get_balance(self):        # GETTER — safe read
        return self._balance

    def deposit(self, amount):   # VALIDATED write
        if amount > 0:
            self._balance += amount
            print(f"Deposited {amount}. Balance: {self._balance}")
        else:
            print("Amount must be positive.")

    def withdraw(self, amount):
        if 0 < amount <= self._balance:
            self._balance -= amount
            print(f"Withdrew {amount}. Balance: {self._balance}")
        else:
            print("Invalid withdrawal.")

acc = BankAccount("Wanjiru", 5000)
acc.deposit(1000)      # Deposited 1000. Balance: 6000
acc.withdraw(-500)     # Invalid withdrawal.
print(acc.get_balance()) # 6000
_balanceSingle underscore = private by convention. Don't access it directly from outside.
get_balance()Getter — safe read-only access to the private attribute.
deposit() / withdraw()Setters with validation — can only change _balance when inputs are valid.

OOP Pillar 4 — Abstraction: hiding complexity, showing only what's needed
Topic: abstraction · abstract classes · ABC module
🧠 Plain English
Abstraction hides complex implementation details and exposes only the essential features. You interact with a simplified interface — you don't need to understand how it works internally, only what it does.
🌍 Kenyan analogy — Driving a car in Nairobi
You press the accelerator and the car moves faster. You don't need to understand fuel injection, combustion, or gear ratios. The complex machinery is hidden. You just use the steering wheel and pedals — the simple public interface.
python
from abc import ABC, abstractmethod

# Abstract class — a blueprint that can't be used directly
class Shape(ABC):
    @abstractmethod
    def area(self):
        pass    # subclasses MUST implement this

    @abstractmethod
    def perimeter(self):
        pass

# Concrete implementation — provides actual logic
class Circle(Shape):
    def __init__(self, r): self.r = r
    def area(self):      return 3.14 * self.r ** 2
    def perimeter(self): return 2 * 3.14 * self.r

c = Circle(5)
print(c.area())        # 78.5
print(c.perimeter())   # 31.4

# Shape() alone would raise TypeError — can't instantiate abstract class
ABCAbstract Base Class — makes Shape a template that cannot be instantiated directly.
@abstractmethodForces every subclass to implement this method. If they don't, TypeError is raised.
Shape()Cannot be created directly — it's a blueprint only. Must use a concrete subclass like Circle.

Section B While Loops, Errors & Pseudocode
B·I
While loop that keeps asking for a valid percentage mark (0–100)
Topic: while loops · break · continue · input validation
🧠 Plain English
Setting the condition to True means the loop runs forever — until it hits a break. This is the standard pattern for input validation: keep asking until the answer is valid, then escape.
🌍 Analogy — Safaricom SIM registration
The system keeps asking for your ID number until it's valid. Type garbage — it asks again. Type an ID that's too short — asks again. Only when the ID is valid does it proceed (break). That's a validation loop.
python
while True:        # loop forever until we break
    try:
        mark = int(input("Enter a percentage mark (0–100): "))
    except ValueError:
        print("Invalid mark. Enter a value between 0 and 100.")
        continue       # skip to top of loop

    if 0 <= mark <= 100:
        print(f"Mark recorded: {mark}")
        break          # valid — exit loop
    else:
        print("Invalid mark. Enter a value between 0 and 100.")
while TrueLoops forever. Only exits via break. Called an "infinite loop with a guarded exit".
try / exceptHandles risky int() conversion. If text is typed, except runs instead of crashing.
0 <= mark <= 100Chained comparison — Python allows this. Same as mark >= 0 and mark <= 100.
breakExits the while loop immediately.
continueSkips rest of this iteration and jumps back to the top.

B·II
What error occurs if the user types "eighty"? How do you prevent it?
Topic: ValueError · try/except · exception handling
⚠️ The Error — ValueError
int("eighty") raises a ValueError. Python cannot convert the word into an integer. Without protection, the entire program crashes:

ValueError: invalid literal for int() with base 10: 'eighty'
💡 Prevention — try/except
Wrap the risky code in a try block. Python tries it; if it raises the named error, the except block runs instead of crashing. Program continues normally.
python
try:
    mark = int(input("Enter mark: "))  # risky line
    print(f"You entered: {mark}")
except ValueError:
    print("That's not a number! Enter digits only.")
    # program continues — does NOT crash

What is pseudocode? Write pseudocode for the validation loop.
Topic: pseudocode · algorithm design · computational thinking
🧠 What is pseudocode?
Pseudocode is a planning tool — write the logic in structured plain English before writing actual code. It's not Python, not any specific language — just human-readable steps. Goal: think through what should happen before worrying about how to write it.
🌍 The blueprint analogy
An architect draws a blueprint before construction. The blueprint is not the building — it's the plan. Pseudocode is your software blueprint. It separates logic design from syntax so you can solve them one at a time.
START
REPEAT indefinitely: Display "Enter a percentage mark (0 to 100):" Read the user's input as raw text
IF input is not a whole number THEN Display "Invalid mark. Enter a value between 0 and 100." Go back to top of loop
Convert input to integer, store as mark
IF mark is between 0 and 100 inclusive THEN Display "Mark recorded: " + mark Exit the loop ELSE Display "Invalid mark. Enter a value between 0 and 100."
END REPEAT
END

C·I
Write the calculate_bmi function with a docstring
Topic: def · docstrings · return · round()
🧠 Plain English
A function is a named, reusable block of code. Write the BMI formula once; call it whenever needed. Functions make your code easier to test, read, and update.
🌍 Analogy — Chapati recipe
A recipe card for chapati is like a function. You follow the card every time you want chapati — you don't reinvent it. Pass in different amounts (arguments) and it adjusts. One recipe, many uses.
💡 Docstrings
A docstring is a triple-quoted string right after the function signature. It documents what the function does, its inputs, and output. Not executed — just documentation. Accessible via help(calculate_bmi).
python
def calculate_bmi(weight_kg, height_m):
    """
    Calculate the Body Mass Index (BMI).

    Parameters:
        weight_kg (float): Person's weight in kilograms.
        height_m  (float): Person's height in metres.

    Returns:
        float: BMI rounded to 2 decimal places.
    """
    bmi_value = weight_kg / (height_m ** 2)
    return round(bmi_value, 2)
defKeyword that starts a function definition.
weight_kg, height_mParameters — named placeholders for values passed in at call time.
"""..."""Docstring — documentation. Not executed.
bmi_valueMeaningful variable name for the result (required by the question).
height_m ** 2Height squared. ** = "to the power of".
round(..., 2)Rounds to 2 decimal places. 22.857... → 22.86.
returnSends the result back to the caller. Without return, function returns None.

Section D Student Grade Management System — Full Program
D
Complete program: get_grade(), collect_scores(), generate_report() and main
Topic: modular design · lists · dicts · enumerate · separation of concerns
🧠 Modular design — Separation of Concerns
Break a big problem into small, focused functions — each doing exactly one job. The main program only coordinates them. This is one of the most important software engineering habits.
🏷️
get_grade(score)
Score in → letter grade out. Single responsibility.
📥
collect_scores(n)
Handles all input — collects n valid scores. Returns a list.
📊
generate_report(scores)
Calculates statistics from list. Returns a dictionary.
🎯
Main program
The coordinator — calls each function and displays output.
python — complete program
# ─────────────────────────────────────────────
#  STUDENT GRADE MANAGEMENT SYSTEM
#  BBIT 1.2 | JKUAT | Group 3
# ─────────────────────────────────────────────


def get_grade(score):
    """Return the letter grade for a score (0–100)."""
    if   score >= 90: return 'A'
    elif score >= 80: return 'B'
    elif score >= 70: return 'C'
    elif score >= 60: return 'D'
    else:             return 'F'


def collect_scores(n):
    """
    Collect n valid integer scores (0–100) from the user.

    Parameters:
        n (int): Number of scores to collect.

    Returns:
        list: A list of n valid integer scores.
    """
    scores = []

    for i in range(1, n + 1):
        while True:
            try:
                score = int(input(f"Enter score for student {i}: "))
            except ValueError:
                print("Please enter a whole number.")
                continue
            if 0 <= score <= 100:
                scores.append(score)
                break
            else:
                print("Score must be between 0 and 100.")

    return scores


def generate_report(scores):
    """
    Generate a summary report from a list of scores.

    Returns:
        dict: highest, lowest, mean, pass_count
    """
    highest    = max(scores)
    lowest     = min(scores)
    mean       = sum(scores) / len(scores)
    pass_count = sum(1 for s in scores if s >= 50)

    return {
        "highest":    highest,
        "lowest":     lowest,
        "mean":       round(mean, 2),
        "pass_count": pass_count
    }


# ─── MAIN PROGRAM ──────────────────────────────
num_students = int(input("How many students? "))

all_scores = collect_scores(num_students)
report     = generate_report(all_scores)

print("\n========== GRADE REPORT ==========")
print(f"Highest score  : {report['highest']}")
print(f"Lowest score   : {report['lowest']}")
print(f"Average score  : {report['mean']:.2f}")
print(f"Students passed: {report['pass_count']} / {num_students}")
print("==================================")

print("\nIndividual grades:")
for idx, sc in enumerate(all_scores, 1):
    print(f"  Student {idx}: {sc} — {get_grade(sc)}")
scores = []Empty list. Filled one score at a time using append().
scores.append(score)Adds one item to the end of the list.
max() / min()Built-ins — highest or lowest value in a list.
sum(1 for s in scores if s >= 50)Generator expression — counts items that meet a condition.
return {...}Returns a dictionary. Access with report["highest"], etc.
enumerate(all_scores, 1)Gives both the index (starting at 1) and the value at each step.
